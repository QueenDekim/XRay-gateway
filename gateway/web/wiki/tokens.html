API-токены

Откройте настройки пользователя → API. Укажите название и срок действия от 1 до 365 дней или включите «Без окончания». При включённой 2FA подтвердите выпуск, перевыпуск и отзыв кодом аутентификатора или резервным кодом. Панель показывает полный токен один раз; на диске хранится SHA-256 хеш.

Используйте Authorization: Bearer <token>. Токен имеет права владельца: обычный пользователь не может менять профили, IP-списки и RouterOS. Отзыв, истечение срока, удаление пользователя, смена пароля, прав или состояния 2FA прекращают доступ по токену.

Можно иметь до 20 действующих токенов. Выпуск, просмотр списка и отзыв требуют сессию панели и CSRF для POST. Bearer-токен не даёт доступ к этим операциям или HTML-страницам. На защищённых API-маршрутах неверный Authorization возвращает 401 даже при наличии действующей cookie.

Перевыпуск заменяет секрет, сохраняя имя и точную дату окончания, включая отсутствие срока. Старый токен сразу перестаёт работать. Истёкший токен нужно создать заново. Секрет нового токена показывается один раз.

GET /api/account/tokens

user (panel session)

Метаданные только собственных токенов: id, name, prefix, created_at, expires_at и active. Секрет и хеш не возвращаются. expires_at равен null для токена без окончания.

POST /api/account/tokens/create

user (panel session)

Создаёт токен и возвращает 201 с полным token, метаданными item и обновлённым user. name обязателен; days по умолчанию 90. no_expiry: true создаёт токен без окончания и отменяет days; expires_at будет null. no_expiry принимает только логическое значение и по умолчанию false. При включённой 2FA обязателен code. Повторно использованный код отклоняется. Пять неудачных операций безопасности за 15 минут блокируют следующие попытки с нарастающей задержкой. Максимум 30 запросов безопасности в минуту на пользователя.

Запрос

{
  "name": "Monitoring",
  "days": 90,
  "code": "123456",
  "no_expiry": false
}

POST /api/account/tokens/revoke

user (panel session)

Отзывает собственный токен по id. Следующие запросы с ним возвращают 401. Отзыв закрывает связанные терминалы RouterOS. При включённой 2FA требуется новый code. Ошибка кода сохраняет токен.

Запрос

{
  "id": "token-id",
  "code": "123456"
}

Ответ

{
  "ok": true,
  "user": {
    "id": "user-id",
    "role": "operator",
    "recovery_remaining": 8
  }
}

POST /api/account/tokens/reissue

user (panel session)

Заменяет собственный токен по id и возвращает 201 с token, item и user. При включённой 2FA обязателен новый code. Имя и expires_at сохраняются, включая null; id и секрет меняются. Старый токен и его терминалы RouterOS прекращают работу.

Запрос

{
  "id": "token-id",
  "code": "123456"
}
