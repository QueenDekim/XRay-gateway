API-токены

Откройте своё имя → API. Укажите название и срок действия от 1 до 365 дней или включите «Без окончания». При включённой 2FA подтвердите каждый выпуск кодом аутентификатора или резервным кодом. Панель показывает полный токен один раз; на диске хранится SHA-256 хеш.

Используйте Authorization: Bearer <token>. Токен имеет права владельца: обычный пользователь не может менять профили, IP-списки и RouterOS. Отзыв, истечение срока, удаление пользователя, смена пароля, прав или состояния 2FA прекращают доступ по токену.

Можно иметь до 20 действующих токенов. Выпуск, просмотр списка и отзыв требуют сессию панели и CSRF для POST. Bearer-токен не даёт доступ к этим операциям или HTML-страницам. На защищённых API-маршрутах неверный Authorization возвращает 401 даже при наличии действующей cookie.

GET /api/account/tokens

user (panel session)

Метаданные только собственных токенов: id, name, prefix, created_at, expires_at и active. Секрет и хеш не возвращаются. expires_at равен null для токена без окончания.

POST /api/account/tokens/create

user (panel session)

Создаёт токен и возвращает 201 с полным token, метаданными item и обновлённым user. name обязателен; days по умолчанию 90. no_expiry: true создаёт токен без окончания и отменяет days; expires_at будет null. no_expiry принимает только логическое значение и по умолчанию false. При включённой 2FA обязателен code. Повторно использованный код отклоняется. Ограничение: пять операций безопасности за минуту на пользователя.

Запрос

{
  "name": "Monitoring",
  "days": 90,
  "code": "123456",
  "no_expiry": false
}

POST /api/account/tokens/revoke

user (panel session)

Отзывает собственный токен по id. Следующие запросы с ним возвращают 401. Отзыв закрывает связанные терминалы RouterOS.

Запрос

{
  "id": "token-id"
}

Ответ

{
  "ok": true
}
